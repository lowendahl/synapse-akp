# Component: SemanticAssertion Model and Assertion Store## PBI 2.1 — SemanticAssertion model and assertion store### Responsibilities1. Define `SemanticAssertion` — a frozen Pydantic model representing a single fact with independent confidence, source, status, and method.2. Define `AssertionStore` — an append-only in-memory collection that accumulates assertions from all pipeline stages.3. Provide query methods: by subject, by predicate, by confidence range, by status.4. Integrate with `PipelineContext` — assertions are stored in context and flow between stages.### Out of Scope- Confidence gating logic (PBI 2.2).- DuckDB persistence (PBI 6.1/6.2).- Review queue generation (PBI 2.4).- Source layer precedence resolution (PBI 2.3).### Promises- **P-01**: Assertions are immutable after creation (frozen Pydantic model).- **P-02**: AssertionStore is append-only — no assertion is ever removed during compilation.- **P-03**: Each assertion has a unique `assertion_id` (deterministic from content hash).- **P-04**: Conflicting assertions can co-exist — the store does not deduplicate by subject+predicate.- **P-05**: Store supports efficient lookup by subject_id (indexed).### Invariants- **I-01**: `assertion.confidence` is always in [0.0, 1.0].- **I-02**: `assertion.status` is always one of: authored, reviewed, inferred, unresolved, rejected.- **I-03**: `assertion.method` is always one of: pattern, llm, rule, embedding, human.- **I-04**: `assertion.subject_id` is non-empty.- **I-05**: Store length monotonically increases within a pipeline run.### File Layout```compiler/src/kp_compiler/semantic/contracts/├── assertions.py    # SemanticAssertion model├── store.py         # AssertionStore (append-only collection)```
