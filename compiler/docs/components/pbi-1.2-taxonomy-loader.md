# Component: Semantic Taxonomy Configuration Loader## PBI 1.2 — Semantic taxonomy configuration loader### Responsibilities1. Load `semantic-taxonomy.yaml` from a base path (framework default) and optional corpus override.2. Merge corpus taxonomy into base taxonomy (corpus entries override/extend base).3. Expose a `TaxonomyRegistry` that provides:   - All entity type IDs and descriptions (for LLM prompt construction).   - Type hierarchy (parent/child relationships).   - Validation: is a given type ID known?4. Validate taxonomy YAML schema on load (fail with clear errors on malformed input).### Out of Scope- Defining the actual taxonomy content (that's YAML config, not code).- LLM prompt construction (PBI 5.3 — this just provides the labels).- Stoplist loading (separate config file, can be added later).### Promises- **P-01**: Taxonomy is loaded exactly once per compilation; the registry is immutable after construction.- **P-02**: If no corpus override exists, the base taxonomy is used unchanged.- **P-03**: Corpus taxonomy can ADD types or OVERRIDE descriptions, but cannot remove base types.- **P-04**: All type IDs are validated as non-empty strings; duplicates are rejected.- **P-05**: The registry is serializable (for inclusion in LLM context).### Invariants- **I-01**: `TaxonomyRegistry.entity_types` returns a stable sorted list.- **I-02**: Every entity type has an `id` and `description`.- **I-03**: Subtypes reference valid parent types.- **I-04**: No circular parent-child relationships.### File Layout```compiler/src/kp_compiler/semantic/├── config/│   ├── __init__.py│   ├── taxonomy.py          # TaxonomyRegistry + loader│   └── default_taxonomy.yaml  # Framework default taxonomy```### Dependencies- `ruamel.yaml>=0.18` (already a dependency)- `pydantic>=2.8` (for taxonomy schema validation)
