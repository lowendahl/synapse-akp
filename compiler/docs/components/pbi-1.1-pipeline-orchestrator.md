# Component: Semantic Pipeline Orchestrator## PBI 1.1 — Pipeline orchestrator and stage contracts### Responsibilities1. Define the `SemanticStage` protocol — a typed callable that transforms stage input into stage output.2. Define `SemanticPipelineConfig` — an immutable configuration object holding stage sequence, confidence thresholds, and feature flags.3. Implement `SemanticPipeline` — the orchestrator that runs stages sequentially, threading context through each stage.4. Define shared stage boundary contracts: `PipelineContext` (accumulated state passed between stages), `StageResult` (what each stage returns).5. Emit structured events for observability (stage started, stage completed, stage failed).### Out of Scope- Concrete stage implementations (PBI 1.3–1.4, Epic 3–4).- DuckDB writing (Epic 6).- LLM integration (Epic 5).- Taxonomy loading (PBI 1.2 — the pipeline receives a loaded taxonomy, does not load it itself).### Promises- **P-01**: Every stage receives a frozen snapshot of `PipelineContext`; stages cannot mutate prior state.- **P-02**: Stage failures are caught and stored as diagnostics; the pipeline continues with remaining stages unless `fail_fast=True`.- **P-03**: The pipeline is synchronous by default; async stages are awaited individually.- **P-04**: Zero domain knowledge in the orchestrator — it knows stage order, not domain semantics.- **P-05**: Stages are composable — the pipeline accepts any `list[SemanticStage]` at construction.### Invariants- **I-01**: `PipelineContext.assertions` is append-only within a compilation run.- **I-02**: `PipelineContext.candidates` grows monotonically — no stage removes candidates.- **I-03**: Each stage's output is validated against its Pydantic contract before being merged into context.- **I-04**: The pipeline emits exactly one `StageCompleted` event per stage (even on failure).- **I-05**: No circular dependency between pipeline and stages — pipeline imports protocols only.### File Layout```compiler/src/kp_compiler/semantic/├── __init__.py├── pipeline.py          # SemanticPipeline orchestrator├── contracts/│   ├── __init__.py│   ├── context.py       # PipelineContext│   ├── stages.py        # SemanticStage protocol, StageResult│   └── candidates.py    # SemanticCandidate (shared input/output model)```### Dependencies- `pydantic>=2.8` (stage contracts)- `kp_compiler.contracts.protocols` (Diagnostic, Severity — reused from existing compiler)- `kp_compiler.events.bus` (EventBus — reused for observability)### Test Strategy- Unit tests for pipeline orchestration (mock stages).- Contract validation tests (invalid stage output → diagnostic).- Event emission tests (correct events fired in order).- Fail-fast vs. continue-on-error behavior.
